Get maki

Three pieces: the firmware for your badge, maki desktop for your computer, and the browser extension. They’re built from public commits, and they go together: this firmware and this maki desktop both speak version {{protocol:firmware}} of maki’s link protocol.

maki firmware

preview {{date:firmware}} · maki-firmware {{commit:firmware}} · protocol {{protocol:firmware}}

For a DEF CON 34 badge’s core module. It replaces the badge’s loader, kernel and apps, and leaves Baochip’s own boot stage alone. Three files, copied onto the badge like onto a USB stick:

{{files:firmware}}
  1. Put the badge in update mode: hold one of its buttons while you press reset, or while you plug it in. It comes up as a drive called BAOCHIP.
  2. Copy loader.uf2, xous.uf2 and swap.uf2 onto it, making sure each is written before the next (sync after each, on Linux).
  3. Eject the drive and press a button on the badge. maki boots, formats its encrypted storage, and starts setup.
Flashing, step by step First boot The release on GitHub

Already running maki? Flash this one the same way, once: your PIN, phrase, name and apps stay, in maki’s encrypted storage. Update maki desktop with it. From then on, maki desktop’s Updates card puts new firmware on maki for you, and updates itself.

maki desktop

{{version:desktop}} for Linux, x86-64 · maki-desktop {{commit:desktop}} · {{size:desktop}}

The tray app that links maki to your computer: it keeps maki’s clock verified and its backups encrypted, installs apps, and is the wallet, the SSH agent, sudo’s plugin and the extension’s way to maki. It holds no keys. One AppImage, for any recent Linux:

{{files:desktop}} 
chmod +x {{name:desktop}}
./{{name:desktop}}
sudo usermod -aG dialout $USER     # once: then log out and in

The group lets you reach maki’s serial port (on Arch it’s uucp). Plug maki in and unlock it: maki desktop finds it and links by itself. macOS and Windows builds come from the same source (npm run dist:mac, npm run dist:win), but haven’t been tried on those systems yet.

The browser extension

{{version:extension}} · Chrome, Chromium, Brave, Edge, Vivaldi · Firefox 140 and later, Zen

Fills the logins and one-time codes maki approves, and gives sites maki’s Ethereum, Solana and Nostr accounts. It isn’t in the browsers’ stores yet, so it’s loaded by hand. Passkeys don’t need it: maki is a FIDO2 security key to any browser.

{{files:extension}}

Chrome and the like

Unzip it, open chrome://extensions, turn on Developer mode, choose Load unpacked and pick the unzipped folder.

Firefox, Zen and the like

Open about:debugging, This Firefox, Load Temporary Add-on, and pick the .xpi. It lasts until the browser restarts. Firefox Developer Edition and Nightly, and Zen, can keep it for good.

Then

In maki desktop, Connections, Browsers, choose Set up, so the extension can reach it.

Checking the files

Every file has a SHA-256 sum.

They’re in the tables above, and in a SHA256SUMS file beside each release: the firmware’s, and maki desktop’s and the extension’s. In the folder you downloaded them to:

sha256sum -c SHA256SUMS          # each file: OK

Each release is built from the commit it names, in public repositories, so you can build it yourself instead.

Building them yourself

From source, start to finish.

The firmware

A fork of Xous. It needs Rust and the Xous toolchain that goes with it, which the first command installs.

git clone \
  https://github.com/KaraZajac/maki-firmware xous-core
cd xous-core
cargo xtask install-toolkit
cargo xtask baosec-lite maki-launcher~flash \
  maki-keys vault2 maki-link maki-apps maki-app-host
# target/riscv32imac-unknown-xous-elf/release/*.uf2

maki desktop and the extension

Node and npm; and Rust, for sudo’s plugin, which the AppImage carries.

git clone https://github.com/KaraZajac/maki-desktop
cd maki-desktop
npm install
npm run dist:linux        # dist/*.AppImage
npm run build:extension   # extension/dist/
