maki

A security key that shows you what you’re signing. Open-source firmware for the DEF CON 34 badge: logins and passkeys, SSH and git, sudo, wallets for Bitcoin, Ethereum, Monero and Solana, and apps anyone can write — every one of them approved on the badge’s own screen, with a button.

Rust · Xous · WebAssembly and native apps · DEF CON 34 badge · Linux · MIT

Early development maki runs on a DEF CON 34 badge: setup, and the link to maki desktop with its clock verified. The rest runs in the emulator, and against a stand-in that runs maki’s own code, and is being tried on a badge now. Nobody has audited it.

The idea

A touch proves you were there. Not what you said yes to.

Tap a YubiKey and whatever your computer asked for gets signed. The key can’t tell you what that was, so neither can you. The DEF CON 34 badge’s core module is a security key with a 128×128 screen and three buttons, so maki puts the request on the screen and waits for you to press. Malware on your computer can ask. It can’t press.

  • THE SITEThe hostname the browser reports for the page that’s asking — never something the page says about itself.
  • THE SERVER AND THE COMMITFor SSH, the user you’re signing in as, and the server’s host key when ssh passes it on. For git, the commit itself: its subject and author, read from the bytes maki signs.
  • THE COMMANDFor sudo, the command whole, quoted so nothing can hide in it, what it’s given to run with, and who asked, where.
  • THE MONEYEvery payment, the change and the fee, a page each, before a transaction is signed. Token transfers and approvals spelled out.
  • THE APPBefore anything installs: what it is, who signed it, and each permission it wants, in its developer’s own words.
  • NOTHING UNSEENNo answer is a no, and an ask can’t be answered unseen: a press made before it appeared, or while something covered it, redraws it rather than answering it.

What it does

Everything that holds a secret, on maki.

  • LOGINS AND ONE-TIME CODESClick into a login field and the browser extension asks maki: it shows the site, you press, the login fills. Codes wait for a verified clock, so a computer that lies about the time can’t collect them for later.The extension
  • PASSKEYSStraight to the browser over FIDO2, no maki software needed. Their keys come from the recovery phrase, so a restored maki still opens every site it signed you up for.Passkeys
  • SSH AND GITAn SSH key from your phrase, with maki desktop as the agent ssh and git talk to. A certificate authority too; and OpenPGP, minisign and age keys that sign and open files only when you say.SSH, git and files
  • SUDO, WITH A YES ON MAKIEvery command sudo would run waits for maki, shown whole. maki’s yes is a signature the plugin checks against a key only root can change, so malware with your password still can’t say it.sudo
  • WALLETSBitcoin (multisig too), Ethereum, Monero and Solana, in maki desktop, in the wallet software you use, and for sites. Addresses as QR codes that never touch the computer; Bitcoin and Ethereum by QR code, with no cable at all.Wallets
  • NOSTRA Nostr key maki holds, for sites through the extension and for Nostr apps through maki desktop as their bunker. Every event shown before it’s signed, hashed by maki from what it showed you.Nostr
  • A CLOCK IT CAN TRUSTThe badge has no battery. maki builds Roughtime requests, maki desktop carries them to three public servers, and maki checks the signed answers itself: it needs two that agree.The time
  • BACKUPS THE COMPUTER CAN’T READmaki desktop keeps your logins, codes and passkeys, encrypted with a key from the recovery phrase. Never the PIN: a backup file is exactly what someone would try PINs against.Backups

Signatures are checked against the reference implementations: Bitcoin’s against rust-bitcoin and Bitcoin Core’s own consensus code, Ethereum’s against alloy, Solana’s against its own runtime, OpenPGP’s against GnuPG; a regtest Monero node takes maki’s transactions and mines them. The extension is tested in real Chromium and Firefox, and sudo’s plugin with the real sudo.

On the badge

Three buttons. No back button.

One press, one meaning

The centre confirms whatever the bottom line of the screen names: open, allow, sign, the digit under the cursor. Left and right move — to the next app, the next page of a transaction, from allow to deny. Both together open the menu.

Going back, cancelling and refusing are always something the screen offers and the centre confirms, so a press never does something the screen didn’t say.

A PIN that gives nothing away

Asked at every boot, a digit at a time. Each position starts on a random digit, so the number of presses says nothing about the PIN. Five wrong in a row wipe everything it protects, and the count survives pulling the plug.

One recovery phrase

Twenty-four words from the hardware random number generator, shown on maki and checked back. They’re the root of everything that can’t be made again — the wallets, the backup key, the passkeys — and to restore, they go back in on maki itself, never typed into a computer.

A name of its own

The first time it starts, a maki picks a name, a maki roll — natto, uni, umekyu, tamago, one of thirty-two — and keeps it. Its home screen says it, and so does maki desktop.

A clock when it rests

maki’s bar shows the time. After a minute with nothing pressed, maki’s own screens give way to a clock the size of the screen, which moves a few pixels each minute so the OLED doesn’t burn in. Any button brings back what was there, and does nothing else.

First boot, step by step

maki desktop

A tray app that holds no keys.

maki desktop is the only thing that talks to maki. It keeps the link and the time, keeps the encrypted backups, installs apps from the store or from a file, and is a wallet for maki’s accounts, the SSH agent, sudo’s plugin and the bridge for the extension and for Nostr apps. Whatever it asks for, maki shows you first.

Apps

{{apps:count}} apps in the store, each rebuilt from its source.

Anyone can write an app for maki, in Rust, and sideload it without flashing firmware, or send it to the maki store. Before one installs, maki goes through it on its own screen, the way it goes through a transaction: the name and version, where it’s from, the developer’s key, and each permission it wants, with the developer’s reason.

{{apps:strip}}

A bar no app can draw

While an app is open, the top line is maki’s: the app’s name, a mark on a sideloaded app, “typing” while it types, and the clock. No app can pass for maki’s own screens, and maki never asks for the PIN while one is open.

Signed twice

A store app carries its developer’s signature and the store’s, whose keys follow The Update Framework’s pattern, so no single stolen key can push an update. The store’s CI rebuilds each one from its public source, byte for byte.

Sandboxed, or confined

WebAssembly apps run in an interpreter, with a cap on memory and fuel, reaching only what the host hands them. Native apps run in a process maki’s kernel confines before any of their code runs.

The hardware

The DEF CON 34 badge’s core module.

The badge is two boards. maki runs on the removable core module, which works on its own over USB-C: a RISC-V chip with an MMU, a screen, three buttons and a camera, already running Xous, the Rust microkernel maki is built on.

ChipBaochip-1x · VexRiscv RV32-IMAC at 350 MHz, with an MMU · four PicoRV32 I/O cores
Screen and input128×128 mono OLED · three buttons, plus reset
CameraGC2145 · QR codes
USB2.0 high speed · FIDO, serial and a keyboard at once
Storage4 MiB on-chip RRAM · 4 MiB encrypted database · 8 MiB encrypted swap
Security blocksAES in the CPU · a hardware RNG · key slots · one-way counters

Before you flash

Read this first.

A one-way door

maki runs in the badge’s developer mode, and turning that on permanently erases the badge’s factory secrets and everything the stock vault was holding: TOTP codes, passwords, passkeys. Move those somewhere else first.

Not a vault

maki protects your keys from malware on your computer: nothing is signed without a press, with the details on screen. It doesn’t protect them from someone who has your badge: in developer mode anyone can flash their own firmware and read what’s stored. Treat it like a Flipper, and keep the wallets to pocket money.

Passwords are the weak case

A passkey or a signature never leaves maki. A password or a code does: once you press, it’s on the computer. What maki stops is quiet extraction, since nothing leaves without a press for that site. Where a site offers passkeys, use them.

DEF CON 34 badges only

Developer mode is the way in, and retail baosec units ship with it switched off for good. The audience is the badges already out there.

Unaudited

This is hobby firmware, in early development. Nobody has audited it. The security model says what it protects you from, and what it doesn’t.
