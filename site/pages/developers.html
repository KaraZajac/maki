Build for maki

An app for maki is Rust, built for WebAssembly or as native code maki’s kernel confines. Write one, try it in the simulator, sideload it onto your own maki, and send it to the store. Or work on maki itself: all four repositories are public.

An app

It draws, then waits.

A cdylib crate with a maki.toml beside its Cargo.toml. The app draws on the screen below maki’s bar, waits for the next event, and returns from main when told to exit. With kind = "native" in its manifest, the same source builds as a native app.

maki.toml

id = "org.example.dice"  # yours for good
name = "Dice"
version = 1              # only goes up
label = "1.0"
storage = 1              # KiB
memory = 64              # KiB
backup = true
description = "Rolls dice."
icon = "icon.png"        # 64x64, light on dark

[permissions]            # the owner reads why
keys = "For a signing key of its own."

src/lib.rs

#![no_std]

use maki_app::*;

fn main() {
    let _ = menu(&["Reset"]);
    loop {
        screen::clear(Color::Dark);
        screen::text_centred(40, "Hello, maki!",
            Style::Bold, Color::Light);
        screen::present();
        match wait(None) {
            Event::Centre => log("pressed"),
            Event::Menu(0) => log("reset"),
            Event::Exit => return,
            _ => {}
        }
    }
}

maki_app::main!(main);

The maki tool

Build, sign, simulate, install.

The SDK is the maki-app crate, twenty-seven example apps (the store’s among them) and the maki tool, which builds, packs, signs, checks and simulates apps, and rebuilds a bundle from its source to check it, as the store does.

rustup target add wasm32-unknown-unknown
cargo install --path maki                         # in maki-firmware's sdk/
maki keygen                                     # your developer key, once: keep it safe
maki new dice --id org.example.dice             # a manifest and a first screen
maki build dice                                 # build, pack and sign
maki run target/maki/org.example.dice.maki      # in a terminal: arrows, enter, m for the menu
maki install target/maki/org.example.dice.maki  # through maki desktop; maki asks on its screen

The simulator runs the same .wasm maki does, against a pretend screen and buttons: scripted presses, answers to asks, messages from the computer, QR codes for the camera and tilts for the accelerometer, and a screenshot of the last frame. An app’s keys there come from the BIP39 test phrase, never anything real.

What an app gets

The basics, and what it asks for.

  • THE SCREEN128 by 110 pixels below maki’s bar, one bit each: lines, rectangles, maki’s fonts, bitmaps and QR codes.
  • THE BUTTONSLeft, right and centre as events, and up to six items of its own in maki’s menu, which left and right together open.
  • STORAGEIts own, up to what its manifest asks for, and in maki’s backups if the manifest says so and the owner doesn’t say otherwise.
  • TIME AND RANDOMNESSThe time, and whether it was checked against Roughtime; random numbers from maki’s TRNG.

And, with a permission, each asked for with a line saying why, which maki shows the owner before it installs:

{{perms:table}}

No permission gives an app the recovery phrase, the vault’s logins, codes or passkeys, another app’s keys or storage, the PIN, raw hardware, or a way to press maki’s buttons.

Into the store

Public source, rebuilt byte for byte.

The maki store is a Git repository, as Flipper’s catalogue is: each app’s signed bundle and the commit it’s built from. maki desktop reads it, and maki checks the store’s stamp on each app itself.

  1. Build and sign your app with the SDK, from a commit you’ve pushed, and check that it reproduces: maki reproduce APP.maki DIR.
  2. Open a pull request to maki-apps adding the bundle and an app.toml naming its category, repository and commit.
  3. CI checks it by the rules and rebuilds it from that commit, on the pull request itself.
  4. The store reads the source, checks that what the app asks to do matches what it does, then stamps it and publishes it.

An update is a bundle with a higher version, signed with the same developer key: the store’s stamp alone can’t push one, and neither can yours. Lose your developer key and you can’t update your app, so back it up.

Working on maki

An emulator, and a stand-in.

maki’s firmware runs in an emulator of the badge, screen and buttons included, with builds that stage a scene to look at (a wallet’s payment, an app’s install, the store) and answer maki’s asks themselves. maki desktop is tested against a stand-in for maki that runs maki’s own code, and end to end in the real app.
